Connect an R2 bucket so jobs can read private files from it and deliver outputs back, addressed as `storage://<id>/<path>`. [Storage connections](/storage) covers what that means. This page gets R2 specifically connected.

**What you'll do:**

1. Open the connect dialog and see which credential it wants
2. Create that credential in Cloudflare
3. Connect the bucket
4. Run a job against it

<Frame caption="Rendobar reads job inputs from a connected R2 bucket and delivers outputs back to it, over the same credential.">
  <img src="/images/storage/hero-r2.png" alt="Rendobar reading inputs from and delivering outputs to a Cloudflare R2 bucket, alongside the other storage kinds it connects to" />
</Frame>

## 1. Open the connect dialog

Start in Rendobar, not in Cloudflare. Open [**Storage**](https://app.rendobar.com/storage), click **Connect Storage**, and choose **Cloudflare R2**.

<Frame caption="Four providers. R2, Supabase Storage and Amazon S3 each take their own credential. Anything else that speaks the S3 API goes through S3-compatible.">
  <img src="/images/storage/connect-providers.png" alt="The Connect Storage dialog with four providers: Cloudflare R2, Supabase Storage, Amazon S3 and S3-compatible" />
</Frame>

The dialog opens on a **Key type** switch, because R2 accepts two:

| Key type | Take it when | Fields |
|---|---|---|
| **API token** | You have none yet. Shortest path | The token, the bucket name |
| **Access key and secret** | You already hold an S3 pair | Account ID, bucket, key id, secret |

Both end in the same stored S3 key pair. The token path just derives one for you and then drops the token.

## 2. Create the credential

### Option A: an R2 API token

R2 speaks the [S3 API](https://developers.cloudflare.com/r2/api/s3/api/), but its credentials come from an [R2 API token](https://developers.cloudflare.com/r2/api/tokens/), not an IAM user. In a second tab:

1. Open **R2 Object Storage**, then **Manage API tokens**, then **Create Account API token**.
2. Under **Permissions**, choose **Object Read & Write**.
3. Under **Specify bucket(s)**, choose **Apply to specific buckets only** and pick the one bucket.

Not Admin. Rendobar reads, writes, lists and deletes objects. It never creates or deletes a bucket, and Admin grants both.

<Frame caption="Object Read and Write, scoped to one bucket. Admin Read and Write would also let the token delete buckets.">
  <img src="/images/storage/r2-token-scope.png" alt="Cloudflare's Create Account API Token page with Object Read and Write selected and a single bucket chosen" />
</Frame>

Click **Create Account API Token**. Cloudflare shows the token value once.

<Frame caption="The token value. Cloudflare shows it exactly once, so copy it before leaving the page.">
  <img src="/images/storage/r2-token-created.png" alt="The created token page in Cloudflare, with the token value shown once" />
</Frame>

<Warning>
Leave that page without copying and the token is gone. Cloudflare cannot show it again, and you will have to create another.
</Warning>

### Option B: an access key and secret

Take this if you already hold an S3 pair for the bucket. It needs three things instead of one. The **Account ID** is 32 hex characters, from the R2 overview page. Then the access key id and the secret. Rendobar builds the endpoint, `https://<account-id>.r2.cloudflarestorage.com`, from the account id.

<Frame caption="The key pair path. Account ID, bucket, then the pair, with the endpoint derived from the account id.">
  <img src="/images/storage/r2-dialog-keys.png" alt="The Cloudflare R2 connect dialog on the access key and secret tab, with the account ID, access key ID and secret masked" />
</Frame>

## 3. Connect the bucket

Back in Rendobar, paste the credential and type the bucket name. On the token path you can paste the whole Cloudflare token page instead of the single value. Rendobar picks the token out of it and fills the provider at the same time.

<Frame caption="Pasting the whole token page fills both fields.">
  <img src="/images/storage/r2-dialog-filled.png" alt="The Cloudflare R2 connect dialog with the API token masked and the bucket name filled in" />
</Frame>

Under **More options**, **id** is the short name the bucket will answer to in every job. Rendobar suggests one from the bucket name.

Click **Connect**. Rendobar [proves the credential](/storage#what-happens-when-you-connect) by writing, reading, listing and deleting a test object, and saves only if all four pass. If the bucket does not exist, the dialog says so and offers **Create the bucket and connect**.

<Frame caption="Connected. Write, read, list and delete all passed, and the snippets are the exact strings a job takes.">
  <img src="/images/storage/r2-connected.png" alt="The finish screen showing write, read, list and delete all passing, with copyable source and destinations snippets" />
</Frame>

## 4. Run a job against it

Read an input by putting a `storage://` reference anywhere a job takes a file URL:

```ts
inputs: { source: "storage://demo-bucket/raw/clip.mp4" }
```

Deliver the output by naming the same connection in `destinations`:

```ts
destinations: ["storage://demo-bucket/exports"]
```

Together, in a runnable job:

<CodeGroup>

```typescript SDK
import { createClient, outputUrl } from "@rendobar/sdk";

const client = createClient({ apiKey: process.env.RENDOBAR_API_KEY });

const job = await client.jobs.run({
  type: "ffmpeg",
  inputs: { source: "storage://demo-bucket/raw/clip.mp4" },
  params: {
    command: "ffmpeg -i source -vf scale=1280:-2 -c:v libx264 -crf 23 -c:a copy out.mp4",
  },
  destinations: ["storage://demo-bucket/exports"],
});

console.log(outputUrl(job));
console.log(job.deliveries);
```

```bash cURL
curl https://api.rendobar.com/jobs \
  -H "Authorization: Bearer $RENDOBAR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "ffmpeg",
    "inputs": { "source": "storage://demo-bucket/raw/clip.mp4" },
    "params": {
      "command": "ffmpeg -i source -vf scale=1280:-2 -c:v libx264 -crf 23 -c:a copy out.mp4"
    },
    "destinations": ["storage://demo-bucket/exports"]
  }'
```

</CodeGroup>

That writes `exports/job_ee14ffeecc3f4a1b.mp4`. To name outputs yourself, see [where outputs land](/storage#where-outputs-land). If a delivery comes back failed, its `reason` is explained under [when a delivery fails](/storage#when-a-delivery-fails).

## R2-specific notes

**Revoking.** Delete the token in [**R2 → Manage API tokens**](https://developers.cloudflare.com/r2/api/tokens/) and the connection stops working immediately. To swap a credential without touching job payloads, [rotate it](/storage#rotating-a-credential) instead.

<Note>
Deleting the bucket does not revoke the token. They are separate Cloudflare resources, and a token scoped to "all buckets in this account" still reaches every other bucket you own. Scope tokens to one bucket.
</Note>

**Public URLs.** R2's [r2.dev domain or a custom domain](https://developers.cloudflare.com/r2/buckets/public-buckets/) is what goes in the connection's [Public URL](/storage#public-url) field. A private bucket has no public link and works fine without one.

**Jurisdictions.** A bucket created in the EU or FedRAMP jurisdiction lives on a different endpoint. Set it under **More options** at connect time and Rendobar builds the right one.

**Egress.** R2 charges none, which is the usual reason to deliver here rather than to S3. Cloudflare's [R2 pricing](https://developers.cloudflare.com/r2/pricing/) has the current rates.

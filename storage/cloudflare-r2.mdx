Connect a Cloudflare R2 bucket to Rendobar so that jobs can read files from it and write their outputs back to it. Files in the bucket do not need to be publicly accessible.

After you connect the bucket, you reference objects in it as `storage://<id>/<path>`. For behavior that is the same across providers, refer to [storage connections](/storage).

<Frame caption="Rendobar reading job inputs from a Cloudflare R2 bucket and writing outputs back to it.">
  <img src="/images/storage/hero-r2.png" alt="Rendobar reading inputs from and delivering outputs to a Cloudflare R2 bucket, alongside the other storage kinds it connects to" />
</Frame>

## Prerequisites

You need a Cloudflare account with an R2 bucket, and a credential for that bucket.

R2 implements the [S3 API](https://developers.cloudflare.com/r2/api/s3/api/), but its credentials come from an [R2 API token](https://developers.cloudflare.com/r2/api/tokens/) rather than from an IAM user. Rendobar accepts two kinds of credential for R2, selected with the **Key type** control in the connect dialog.

| Key type | Use when | Required values |
|---|---|---|
| **API token** | You do not already have credentials for the bucket | API token, bucket name |
| **Access key and secret** | You already have an S3 key pair for the bucket | Account ID, bucket name, access key ID, secret access key |

Both options store the same thing. Rendobar exchanges an API token for the S3 key pair that it represents, then discards the token.

The rest of this page uses the API token. To use an existing key pair instead, refer to [Connect with an access key and secret](#connect-with-an-access-key-and-secret).

## 1. Create an R2 API token

To create a token scoped to a single bucket:

1. In the Cloudflare dashboard, go to **R2 Object Storage** > **Manage API tokens**.
2. Select **Create Account API token**.
3. Under **Permissions**, select **Object Read & Write**.
4. Under **Specify bucket(s)**, select **Apply to specific buckets only**, then select your bucket.
5. Select **Create Account API Token**.

Rendobar reads, writes, lists, and deletes objects. It does not create or delete buckets, so **Admin Read & Write** grants more access than it needs.

<Frame caption="Object Read and Write permissions, applied to a single bucket.">
  <img src="/images/storage/r2-token-scope.png" alt="Cloudflare's Create Account API Token page with Object Read and Write selected and a single bucket chosen" />
</Frame>

Cloudflare displays the token value on the next page.

<Frame caption="The created token. Copy the value before you leave the page.">
  <img src="/images/storage/r2-token-created.png" alt="The created token page in Cloudflare, with the token value shown once" />
</Frame>

<Warning>
You cannot view this token again after you leave the page. Copy and record the value. If you lose it, create a new token.
</Warning>

## 2. Connect the bucket

To connect the bucket in Rendobar:

1. In [**Storage**](https://app.rendobar.com/storage), select **Connect Storage**.
2. Select **Cloudflare R2**.

<Frame caption="The Connect Storage dialog, listing Cloudflare R2, Supabase Storage, Amazon S3, and S3-compatible.">
  <img src="/images/storage/connect-providers.png" alt="The Connect Storage dialog with four providers: Cloudflare R2, Supabase Storage, Amazon S3 and S3-compatible" />
</Frame>

3. In **API token**, enter the token. In **Bucket**, enter the bucket name.

You can paste the entire Cloudflare token page instead of the token value. Rendobar extracts the token from the pasted text and selects the provider.

<Frame caption="The R2 connect dialog with the API token and bucket name entered.">
  <img src="/images/storage/r2-dialog-filled.png" alt="The Cloudflare R2 connect dialog with the API token masked and the bucket name filled in" />
</Frame>

4. (Optional) Under **More options**, set **id**. This is the value that jobs use to reference the bucket. Rendobar suggests one based on the bucket name.
5. Select **Connect**.

Rendobar runs its [access checks](/storage#access-checks) against the bucket and saves the connection only if all four succeed. If the bucket does not exist, the dialog offers **Create the bucket and connect**.

<Frame caption="A connected bucket, showing the four access checks and the storage URIs to use in jobs.">
  <img src="/images/storage/r2-connected.png" alt="The finish screen showing write, read, list and delete all passing, with copyable source and destinations snippets" />
</Frame>

## 3. Use the bucket in a job

Reference an object in `inputs` to read it, and the connection in `destinations` to write the output:

<CodeGroup>

```typescript SDK
import { createClient, outputUrl } from "@rendobar/sdk";

const client = createClient({ apiKey: process.env.RENDOBAR_API_KEY });

const job = await client.jobs.run({
  type: "ffmpeg",
  inputs: { source: "storage://demo-bucket/raw/clip.mp4" },
  params: {
    command: "ffmpeg -i source -vf scale=1280:-2 -c:v libx264 -crf 23 -c:a copy out.mp4",
  },
  destinations: ["storage://demo-bucket/exports"],
});

console.log(outputUrl(job));
console.log(job.deliveries);
```

```bash cURL
curl https://api.rendobar.com/jobs \
  -H "Authorization: Bearer $RENDOBAR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "ffmpeg",
    "inputs": { "source": "storage://demo-bucket/raw/clip.mp4" },
    "params": {
      "command": "ffmpeg -i source -vf scale=1280:-2 -c:v libx264 -crf 23 -c:a copy out.mp4"
    },
    "destinations": ["storage://demo-bucket/exports"]
  }'
```

</CodeGroup>

This job writes its output to `exports/job_ee14ffeecc3f4a1b.mp4`. To control output names, refer to [configure output delivery](/storage#configure-output-delivery). For a delivery that fails, refer to [delivery errors](/storage#delivery-errors).

## Revoke access

To revoke Rendobar's access to the bucket:

1. In the Cloudflare dashboard, go to **R2 Object Storage** > [**Manage API tokens**](https://developers.cloudflare.com/r2/api/tokens/).
2. Delete the token used for the connection.

The connection stops working immediately. To replace a credential without changing job payloads, [rotate it](/storage#rotate-a-credential) instead.

<Warning>
Deleting a bucket does not revoke an API token. Buckets and API tokens are separate Cloudflare resources, and a token scoped to all buckets in an account continues to reach every other bucket in that account. Scope tokens to a single bucket.
</Warning>

## Connect with an access key and secret

If you already have an S3 key pair for the bucket, select **Access key and secret** as the **Key type**. This option requires three values instead of one:

| Value | Where to find it |
|---|---|
| **Account ID** | A 32-character hexadecimal string on the R2 overview page |
| **Access Key ID** | Issued with the key pair |
| **Secret Access Key** | Issued with the key pair |

Rendobar builds the endpoint from the account ID, in the form `https://<account-id>.r2.cloudflarestorage.com`.

<Frame caption="The R2 connect dialog on the Access key and secret tab.">
  <img src="/images/storage/r2-dialog-keys.png" alt="The Cloudflare R2 connect dialog on the access key and secret tab, with the account ID, access key ID and secret masked" />
</Frame>

## R2-specific behavior

**Jurisdictions.** A bucket created in the EU or FedRAMP jurisdiction uses a different endpoint. Set the jurisdiction under **More options** when you connect, and Rendobar builds the correct endpoint.

**Public URLs.** Use the bucket's [r2.dev domain or a custom domain](https://developers.cloudflare.com/r2/buckets/public-buckets/) as the connection's [public URL](/storage#public-url). A private bucket has no public domain and works without one.

**Egress.** R2 does not charge for egress. Refer to [R2 pricing](https://developers.cloudflare.com/r2/pricing/) for current rates.
